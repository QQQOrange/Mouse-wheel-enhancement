# v1.9.15：Kelivo 的滚动补偿与细腻模式守护进程

## Kelivo（Flutter）到底读不读系统行数

读，但**只在创建窗口时读一次**。Flutter 的 Windows 引擎在初始化时调用
`SystemParametersInfo(SPI_GETWHEELSCROLLLINES)`，把结果换算成
`scroll_offset_multiplier = lines × 100 / 3`，之后每个 `WM_MOUSEWHEEL`
都按这个缓存值换算像素，**不再刷新**（`flutter_window.cc` 里
`UpdateScrollOffsetMultiplier()` 只在启动时调用）。

所以：

- 细腻模式（系统 1 行）生效**之后**启动的 Flutter 应用，缓存的是 1 行倍率
  （约 33 px/格），我们注入时 ×3 补回 100 px —— 距离正确；
- 在切成 1 行**之前**就启动的应用，缓存的是 3 行倍率（100 px/格），
  再 ×3 就变成 300 px/格 —— 又快又跳。

这一版把 Flutter 明确归到「按比例滚动、读系统行数」，并在日志里记下
`kelivo.exe（FLUTTER_RUNNER_WIN32_WINDOW）` 的实际输出量，方便下次直接核对。

**遇到滚动距离不对时**：让 Kelivo 完全退出再打开（它只在启动时读一次行数），
确保打开时本程序已经在运行（系统 1 行）。

## 细腻模式守护进程会等错进程

守护进程原来只带 `pid` 去 `WaitForExit`。主进程退出后 pid 很快会被复用，
守护进程就会一直等一个毫不相干的程序，等它退出时再把系统行数写回 3 ——
表现为「用着用着滚动手感突然变了」，多个守护进程还会互相覆盖。

现在守护进程同时带**主进程的启动时间**，对不上就立刻退出、不还原；
老格式（只有 pid）仍按原逻辑兼容。

## 屏幕上出现黑白

这不是本程序改的：本程序只读写 `WheelScrollLines`，从不合成键盘事件，
也不碰任何颜色设置。黑白来自 Windows 的「颜色滤镜」（辅助功能 → 颜色滤镜，
快捷键 `Win+Ctrl+C`，`HotkeyEnabled=1` 时生效）。

这一版会在启动时读一次该开关，开着就记一条 WARN，方便下次直接对上号。
