# v1.8.31：把推送也搬到 API 上（tooling）

这台机器上 github.com:443 时通时不通，而 pi.github.com 一直通 —— 结果就是：
发布能成功，git push 却一直超时，远端代码落后好几个版本。

新增 	ools/push-via-api.py：用 GitHub 的 Git Data API 走完"推送"这件事。

## 怎么保证不分叉

关键是**照抄元数据**：author、committer（含时区）、message、parents 全部取自本地提交，
tree 用远端 tree + 本地差异文件重建。这样 API 造出来的 commit **SHA 与本地完全一致**
（v1.8.30 那次实测：9b8fead == 9b8fead），本地和远端是同一条历史，不会出现"远端多一个合并提交"。

## 用法

`
python tools/push-via-api.py            # 推送 main
python tools/push-via-api.py --dry-run  # 只列出会推哪些文件
`

凭据与 make-release.py 同源（git credential fill，即 Windows 凭据管理器里的令牌），
不需要额外配置。
