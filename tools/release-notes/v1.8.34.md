# v1.8.34：修「稍微动一下就 5 倍」——细腻模式的补偿不该参与速度判定

## 原因

细腻模式为了抵消"系统行数被压到 1"，会把 delta **乘 3** 再往下发。
问题是这个乘法发生在**速度判定之前**：

`
delta × 3  →  速度跟踪器看到"每秒 3 倍的单位"  →  阈值 10 格/秒 在真实 3.3 格/秒就满足
`

于是慢滚也会被判成快滚，倍率一路顶到上限 —— 就是你看到的"稍微动一下就 5 倍"。

（这个 bug 只在细腻模式开启时出现。你 14:10 那次启动正好开着细腻模式，所以暴露了。）

## 修法

**补偿只在输出侧做，速度按物理 delta 算。**

- 新增 awDelta：速度跟踪器只吃它；
- 输出侧再乘 ineScale：按比例 / 整格 / 横向三条路径都补；
- **Chromium 系例外**：它们不读系统行数，补了就是 3 倍过冲，所以那边不补（保持不变）。

现在 5× 需要真实 **≈11 格/秒**（原来的阈值语义），不再是 3 倍虚高。

## 顺手加的诊断

每次加速会记一条（每程序每分钟最多一条）：

`
加速判定：xxx.exe 速度 12.4 格/秒（阈值 10）→ 2.35×，细腻 ×3
`

以后有人报"怎么突然加速了"，看这一行就能知道是速度估高了、还是阈值配低了。
