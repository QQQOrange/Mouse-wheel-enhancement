# v1.8.17：细腻模式 —— 量化细 3 倍，且关掉软件一定还原

新增「平滑滚动 → 细腻模式（实验性）」，**默认关闭**。

## 它做了什么

打开之后，运行期间把系统「每次滚动几行」临时改成 **1 行**，注入侧按原行数补偿
（3 行 → 注入量 ×3，距离和原来一模一样）。于是：

- 1 个滚轮单位对应的像素从 **0.5px 降到 0.17px**（3 行时）；
- 尾巴能连续减速到 **20~30px/s**，而不是在 80px/s 处一刀切断；
- Chrome / 记事本这类"按行数换算像素"的程序受益最大。

实测（--scrollsmooth，8 格真实注入 + 真实渲染）：**88.2 px/格**，与没开细腻模式时
完全一致（距离一像素不差），末 10 步 **3 → 2.5 → 1.5 → 1 → 1 → 0.5 → 0.5 → 0.5 px**。

## 还原是硬要求，三条路都验证过

| 退出方式 | 结果 |
|---|---|
| 正常退出（引擎 Dispose / Services.Shutdown） | 3 → 1 → **3** |
| 直接结束进程（模拟崩溃） | 停在 1，**下次启动**按备份还原 → 3，并重新进入 |
| CLI 模式（--measure / --scrollsmooth） | 注册了 ProcessExit 兜底，3 → 1 → **3** |

实现顺序是**先写备份、再改系统**（wheellines.fine.backup），所以改完到崩溃之间也有据可查。
启动时 CleanupFine() 只要看到备份就还原 —— 这就是"被杀进程"那条路。

## 代价（界面上也写了）

- 这期间**所有滚动都由本程序转发**（被排除的应用也一样，否则它们会慢 3 倍）；
- 少数不读系统行数的程序（部分 Electron/Qt 应用）可能滚得偏快 —— 关掉开关立刻恢复；
- 目标窗口权限比本程序高时（管理员程序）注入会被系统拦，这部分仍原样放行，会变慢 3 倍。

## 其它

- 设置窗口自己的滚动换算按补偿倍数修正（不然设置页会只剩 1/3 的滚动量）；
- 自检 +4 条细腻模式断言（默认关、目标行数 1、补偿倍数默认 1）；
- --selftest 351 项、--featurecheck、--frametrace、--scrollsmooth、--smoke、--measure 全 rc=0。
