# v1.8.25：实测推翻了一个三版本的前提，并给你一个开关

## 先说实验结果

新增诊断 --wpfprobe：开一个只有 ScrollViewer 的窗口（不装钩子、不接自己的处理器），
分别投递 delta = 15 / 40 / 120 / 240 的 WM_MOUSEWHEEL，量位移：

| delta | 每次位移 |
|---:|---:|
| 15 | 7.5 px |
| 40 | 20.0 px |
| 120 | 60.0 px |
| 240 | 120.0 px |

**严格成比例** —— WPF 的 ScrollViewer 其实**认 delta 大小**，不是"只认事件个数"。
从 v1.6 起把 WPF 一律归进"整格"，这个前提对文档类是错的。

## 为什么以前没暴露

同一个 WPF 窗口里，ListBox / DataGrid 这类按项滚动的容器**确实**只认事件个数，
而它们和 ScrollViewer 的窗口类名一模一样（都是 HwndWrapper），外部无法区分。

## 所以这一版给你一个开关

名单里右键任意程序 → **滚动语义**：

- **自动**（默认）：按窗口类猜，最稳；
- **按事件（整格）**：列表类应用用，一档一事件，距离永远准；
- **按像素（平滑）**：文档/网页类的 WPF 程序切到这个，立刻变回亚格平滑。

默认仍是"自动"，不改变任何现有行为；只是把"猜错时"的补救权交给你。
