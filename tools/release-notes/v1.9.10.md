# v1.9.10：把平滑滚动真正做成触控板节奏

这一版的重点不是"再多几个参数"，而是把**滚轮 → 页面移动**这条链路的节奏重做一遍。
起因是实测发现：旧版对 Chromium / Electron 只发**一个大事件**，浏览器会一步跳
120~1800px；对触控板/自由滚轮的高频流又按普通滚轮去加速、摊帧，把它拆碎。
两者都表现为"有时候和触控板差很远"。

## 修好的根因

- **Chromium / Electron / Firefox 不再被当成"自带平滑"**：实测它们收到合成滚轮
  事件是立即位移，并不会自己摊帧。现在和浏览器/Office 一样走按像素路径，
  由动画器按显示器刷新率拆成每帧几像素。一个 120 单位的格 ≈ 100ms 连续推进，
  和真实触控板手势同构。
- **触控板 / 自由滚轮默认原样放行**：新增输入流分类器，识别 60~125Hz 的连续流
  （包括"看起来是整格 120，但间隔只有十几毫秒"的流）。这类流本身就是触控板手感，
  默认不接管；只有打开「也增强高精度输入」才会放大。想放大时不再把整条流拆成
  一个个孤立补间。
- **「触控板」预设重定**：旧预设 τ16ms / 惯性 600ms 实测是"40ms 冲完再飘 400ms"，
  与触控板相反；现在改为 τ45ms / 惯性 300ms，单格约 100ms，慢滚不飘。
  旧配置里的这个"预设指纹"会在升级时一次性重映射；自己调过的其他值不动。
- **只有"甩"才给惯性**：普通滚轮两格之间就有 50~150ms 空隙，旧版 30ms 的松手判定
  几乎每格都触发滑行。现在要求"这一段够长 + 峰值够快"才进入滑行，慢滚单格
  只用跟手曲线落地。
- **整格应用（WPF / WinForms / Qt）第一档立即发**：以前要等曲线"欠够一格"才发，
  第一行会晚 50~80ms；现在第一档立刻落地，之后按显示器帧间隔逐档推进。
- **换程序重置速度状态**：在 A 程序快滚到 5×，光标移到 B 程序再滚一格时，
  不再继承 A 的速度/甩动补页。
- **细腻模式不再把自己的设置页滚成 3 倍**：自己的页面会自行乘补偿倍数，
  钩子侧不再重复乘；PPT/WPS 演示也不做行数补偿。
- **单帧上限收紧**：一帧最多 1.5 格（180 单位），避免猛甩时"一帧跨好几格"。

## 新增

- `--wheelcapture [seconds=N]`：只读采集真实滚轮/触控板事件流到
  `wheelcapture.csv`（时间、delta、目标窗口、是否注入），用于校准分类阈值。
- 自检从 392 项增至 421 项：新增触控板流分类、τ45 单格曲线（80~130ms、首帧 ≤8、
  单帧 ≤18）、整格首档立即发、v9 配置迁移等断言。
- `--scrollsmooth` 的总量判据改为"原生距离 ≤ 总量 ≤ 满倍率×1.3"：
  旧判据拿慢速单格基准去要求快滚，加速一生效就误报重复投递。

## 说明

- WPF / WinForms / Qt 的最小粒度就是一格，能做的上限是"第一档立即发 + 每帧一档"；
  浏览器那种亚像素推进需要框架本身认 delta，这是框架限制，不是本程序能绕过的。
- 细腻模式仍会临时改系统「每次滚动几行」，退出/崩溃由守护进程还原；用触控板时
  如果觉得距离不对，优先关掉细腻模式（默认关闭）。
- 本版只改主程序；发布说明里的 SHA256 由 `tools/publish.ps1` 生成后填入。
