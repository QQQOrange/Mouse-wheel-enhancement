# v1.8.13：收尾不再"又慢又突兀" —— 尾巴短了一半，落地更利落

你说的"停止的过程很慢，而且很突兀"，原因不是一处，而是三处叠在一起：

1. **滑行太长**：默认「惯性长度」是 300ms，在 160Hz 上是二十多帧，末尾有一大段都是
   0.5px 的小步 —— 眼睛早读作"快停了"，画面却还在一点点挪。
2. **落地段在减速的末端又把它拖慢**：末 1/10 格用的是 35~50ms 的 τ，越到结尾越稀。
3. **终止是"从低速直接归零"**：最后一步 0.5px / 12ms（约 40px/s），然后一下停住。

## 改了什么

- **默认惯性 300ms → 180ms**（老配置里正好是 300 的会被迁移成 180；你自己调过的值不动）。
  实测 6 格猛甩的总收尾从 359ms 降到 296ms，1 格轻拨 203ms → 186ms。
- **落地段 τ 收到 22~30ms、按滑行 τ 的 0.45 倍取**：最后几个单位不再被越拖越稀，
  落地段从 143ms 缩到 119ms（6 格）、50ms → 44ms（1 格）。
- **尾段提前接管、终止门槛收紧**：剩余 12 单位就按曲线逐个发（原来 8），
  间隔超过 9ms（原 12ms）就收尾，残留 ≤1 单位。
- 依据的判据也同步：--frametrace 的末段速度/落地段、--scrollsmooth 的末段速度回跳，
  都在新参数下重跑过（末段 0 次抽搐，末步空窗 12.3ms）。

## 想要更长/更短的尾巴

「平滑滚动 → 惯性长度」现在默认停在 180ms：**想更利落就往左拉到 60~120**，
**想更像"溜一段"就拉到 260~400**。它只影响松手之后的滑行，不影响滚动过程中的摊帧。
