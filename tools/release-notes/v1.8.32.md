# v1.8.32：Electron / Chromium 里"越装越难滚"修好了

## 问题

你反馈的这个现象非常典型：**打开本软件之后，DeepSeek Harness 里反而更难滚**。

原因不是加速太猛，而是**两套平滑在打架**：

- Chromium / Electron / Firefox 收到一个滚轮事件后，自己会把它摊成 150~250ms 的动画；
- 我们又把同一段位移拆成几十个小事件发过去。

结果是它们对我们发出的**每一个小事件各起一段动画** —— 动画排队、互相打断，
跟手变差、快速连滚时掉帧。所以"关掉本软件反而顺"。

## 现在的做法

对**自带平滑动画**的框架（Chrome_WidgetWin_*、MozillaWindowClass）：

- 加速时**只发一个事件**，delta 直接乘以倍率；
- 平滑交给它们自己 —— 那本来就是它们的原生手感；
- 不做细腻模式补偿（这类框架不看系统行数，按 1/N 补偿会变成 N 倍过冲）。

位移总量仍然准确：一个事件的 delta 就是全部距离。

## 影响范围

| 框架 | 处理 |
|---|---|
| Chromium / Electron / Edge / CEF | **单个事件**，交还原生平滑 ← 本次修复 |
| Firefox / Waterfox | 同上 |
| WPF / WinForms / Qt | 整格（一事件一档），本来就不拆分 |
| 其他（Win32、Office、记事本…） | 我们的亚格平滑（这部分没变） |
