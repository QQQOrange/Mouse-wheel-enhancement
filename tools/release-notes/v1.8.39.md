# v1.8.39：PPT 跳页的真正原因 —— 细腻模式在给 PPT 做 ×3 补偿

## 上一版只修了一半

v1.8.38 把 PowerPoint 归成"按事件滚动"（一格一个事件），方向是对的。
但**细腻模式**还在给每个事件做 ×3 补偿 —— 因为系统行数被压到 1 了，别的框架需要补回来。

PowerPoint 的幻灯片视图**根本不看系统行数**：它只数事件。于是：

`
滚 1 格 → 我们发 3 个事件（×3 补偿）→ PPT 翻 3 页
`

你看到的就是 1 → 3 → 6 → 8。

## 这一版

给"不读系统行数"的窗口加了标识（IgnoresSystemLines）：

| 窗口 | 细腻模式补偿 |
|---|---|
| PPTFrameClass / screenClass | **不补偿**（一格永远只发一个事件） |
| WPF / WinForms / Qt | 照旧补 ×N（它们真的读系统行数） |
| Chromium / Electron | 补 ×N（v1.8.35 已确认它们读） |

现在在 PPT 里：滚一格 = 一个事件 = 翻一页；加速时才按倍率发多个整格。

## 验证

--selftest **373 项**（新增 3 条：PPT 不读系统行数、放映窗口、WPF 需要补偿），全过。
