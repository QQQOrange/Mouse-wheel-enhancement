# v1.8.14：平滑滚动按 Mos 的模型重做

上一版只是把尾巴调短，本质没变。这一版**换掉了出帧的核心算法**，
参考 [Caldis/Mos](https://github.com/Caldis/Mos) 的做法重写。

## Mos 怎么做的（读源码得到的）

Mos 不用"惯性曲线 + 尾段排空"，它只有一个一级低通：

`
目标量 buffer 累积输入
每帧:  step = (buffer - current) * k      // k 是每帧过渡系数
       current += step
       只有 |step| > 死区(约 1px/1 单位) 才真的发出去
       剩余量收敛到死区内 → 补齐/丢弃 → 停
`

要点是**两条**：① 只用一条曲线，没有"跟手 τ → 滑行 τ → 落地 τ → 尾段调度"这四层叠加；
② 有一个**死区**，步长小到看不见时就结束，而不是降到 0.5px 再一点点爬。

## 我们的旧模型为什么会"又慢又黏又突兀"

- 四层 τ 叠加，每一层都在减速的**末端**把速度再压一次 → 尾巴 100~150ms；
- 每步 0.5px、间隔被拉到 12ms 才收尾 → 读作"还在慢慢挪"；
- 终止时从非零速度直接归零 → 突兀。

## 现在

- **一条曲线**：step = 残量 × (1 − e^(−dt/τ))，τ 跟手值 45ms，松手后最多放宽到 1.6×（封顶 90ms）；
  以前允许 400ms —— 那正是"很慢"的来源。
- **死区收尾**：这一帧该走的量 < 1 单位（0.5px）时，若剩量 ≤ 2 单位就一次补齐（≤1px）然后停，
  否则只发 1 单位继续收敛。**不再出现"0.5px 每 12ms 爬一段"**。
- 删掉了「落地段 τ 插值」和「尾段 ln 调度」两套特例，代码路径只剩一条。

## 实测（160Hz，--frametrace，末 6 帧 = 最后 6 次发送）

| 场景 | v1.8.12 | v1.8.13 | **v1.8.14** |
|---|---:|---:|---:|
| 滚一格 总时长 | 203 ms | 186 ms | **170 ms** |
| 连甩三格 | 296 ms | 252 ms | **238 ms** |
| 连甩六格 | 359 ms | 296 ms | **263 ms** |
| 末 6 帧形态 | 1,1,1,1(+12ms),1(+12ms) | 1,1,1,1,1(+12ms) | **1,1,1,1,1,2（每帧 6ms，匀速收敛）** |
