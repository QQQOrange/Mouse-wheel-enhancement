# v1.8.22：一次"没被要求"的工程化体检

你没有提，但这些地方迟早会咬人。四条都改了。

## 1. 钩子里每个事件都跑正则（最危险的一条）

标题正则带 **50ms 超时**，而 Windows 对低级钩子的预算是 300ms 左右。用户随手写一个
.*?foo.*bar.*，每次滚轮都可能卡几十毫秒 —— 表现就是"滚动偶尔整体顿一下"。

现在按**标题字符串缓存判定结果**：同一窗口连续滚动时标题几乎不变，正则真正执行的次数
从"每个事件一次"降到"每次换标题一次"。缓存放在配置快照里，改配置就换新快照，天然不会用错正则。

## 2. 后台线程崩溃 = 无声消失

UI 线程的异常有 DispatcherUnhandledException，WinForms 托盘那条有 ThreadException，
但**后台线程**的异常一条都没接：进程直接结束，日志里一个字都没有；如果当时细腻模式开着，
系统行数还会停在 1 行。

补上 AppDomain.UnhandledException：记日志 → 尝试还原系统行数 → 刷盘。

## 3. 诊断命令会**无声挂死**

我们自己就踩过：--frametrace 遇上另一个实例占着钩子，进程挂了 10 分钟，
没输出、没退出码。现在所有诊断命令都有 120 秒看门狗，超时写日志并 exit 90。

⚠ 这里差点埋一个更严重的 bug：第一版按 -- 前缀判断，而 --minimized 是**开机自启的正常参数** ——
那样每次开机两分钟后程序会被自己杀掉。现在改成**白名单**，只认诊断参数。

## 4. 无障碍

标题栏四个只有图标的控件（总开关、主题、最小化、关闭）补了 AutomationProperties.Name，
读屏软件和 UI 自动化终于能念出它们是什么。

## 顺手体检过、结论是"已经没问题"的

- 配置写盘：临时文件 → File.Replace，断电不会留半个 JSON；损坏文件保留成 .corrupt-时间戳
- 日志：1MB 自动轮转，后台队列 + 刷盘超时
- 单实例：互斥体 + 唤出已有窗口，不是"弹个框就退"
- 更新：SHA256 校验、失败回滚、.old-<ticks> 唯一命名
- 钩子：超时保护、异常一律放行、动画线程死亡时自动降级为原样放行
