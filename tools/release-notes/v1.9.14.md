# v1.9.14：Flutter 应用的滚动补偿与细腻模式守护进程

## Kelivo（Flutter）为什么卡顿

Flutter 桌面端不读 Windows 的「每次滚动几行」：引擎自己把 `WM_MOUSEWHEEL` 的
delta 按 `delta / 120 × 50` 换算成逻辑像素，再交给框架。也就是说**一格永远是 50 px**，
跟系统行数无关。

细腻模式为了抵消「系统被改成 1 行」，会在注入时把量乘 3。对浏览器是对的（Chrome
确实读系统行数），对 Flutter 就是三重放大：一格变 150 px，一次三格甩出去 450 px，
每帧位移跟着变大，看起来就是「又快又卡」。

修法：把 `FLUTTER_RUNNER_WIN32_WINDOW` / `FLUTTERVIEW` 加进语义表，标成
**按比例滚动 + 不做行数补偿**。距离回到 1×，帧步长变小，观感就顺了。

## 细腻模式守护进程会等错进程

守护进程原来只带 `pid` 去 `WaitForExit`。主进程退出后 pid 很快会被复用，
守护进程就会一直等一个毫不相干的程序，等它退出时再把系统行数写回 3 ——
表现为「用着用着滚动手感突然变了」，多个守护进程还会互相覆盖。

现在守护进程同时带**主进程的启动时间**，对不上就立刻退出、不还原；
老格式（只有 pid）仍按原逻辑兼容。

## 屏幕上出现黑白

这不是本程序改的：本程序只读写 `WheelScrollLines`，从不合成键盘事件，
也不碰任何颜色设置。黑白来自 Windows 的「颜色滤镜」（辅助功能 → 颜色滤镜，
快捷键 `Win+Ctrl+C`，`HotkeyEnabled=1` 时生效）。

这一版会在启动时读一次该开关，开着就记一条 WARN，方便下次直接对上号。
