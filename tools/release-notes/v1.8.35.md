# v1.8.35：细腻模式在 Electron / Chromium 里变慢 —— 补偿补到点上

## 我上一版的判断错了

v1.8.32 我假设"Chromium 不读 Windows 的每格行数设置"，所以**没有**给它做细腻模式补偿。
你的实测推翻了它：**开着细腻模式时 DeepSeek Harness 明显变慢**，其它软件正常。

原因就是补偿漏了这一类目标：

| 目标 | 细腻模式（系统行数 3 → 1） |
|---|---|
| WPF / WinForms / Qt | 我们把注入量 ×3，距离不变 ✅ |
| Chromium / Electron | 原样放行 → 它们真的只滚 1 行 → **距离只剩 1/3** ❌ |

## 现在的做法

对自带平滑的框架（Chromium / Electron / Firefox）同样补：

- **没加速**：把 delta × N 转发出去（而不是原样放行）；
- **加速了**：输出 倍率 × N，同样一个事件发完。

于是三种框架在细腻模式下距离都保持一致，只有"每档更细"这一项收益。

## 为什么细腻模式值得开着

- 系统行数 1 行 → 每档 20px（原来 60px），鼠标一格能滚出**三倍细**的步长；
- 配合加速，快甩照样能滚远；
- 退出 / 崩溃 / 重启都会还原（RunOnce 兜底）。
