# v1.9.0：可靠性内核三项 —— 语义表驱动 / 自动降级 / 安全模式

这一版不是加功能，而是把这几周反复踩的坑从**根上**堵住。功能类（每应用手感、中键拖拽、横向平滑等）在下一版，说明见末尾。

## 1. 语义判定改成**表驱动**

以前是三条手写 if 链（按事件 / 自带平滑 / 不读系统行数），加一个窗口类要改三处，**非常容易漏**——
WPS 演示的 PP12FrameClass 就这么漏掉了（和 PPTFrameClass 只差一个字母），结果滚一格翻三页。

现在只有一张表 Rules：

`
HwndWrapper[        按事件
WindowsForms10.     按事件
PPTFrameClass       按事件 + 不读系统行数
screenClass         按事件 + 不读系统行数
Chrome_WidgetWin_   自带平滑
MozillaWindowClass  自带平滑
+ Qt（版本号段专用判定）、PP12/14/15（专用判定）
`

新增类名 = 加一行；--selftest 会**自动遍历整张表**校验每条规则的分类与补偿标记，
不可能再出现"某个入口忘了加"。

## 2. 自动降级：慢回调连续 3 次就切直通 30 秒

之前只有单次回调 >150ms 才轮换钩子。现在：

- 单次 >50ms 记一次，**连续 3 次** → 自动进入"直通模式"30 秒；
- 直通期间不加速、不摊帧、不做细腻补偿 —— 滚动行为与不装本程序一致；
- 30 秒后自动恢复，日志留痕。

这是"宁可少一点加速，也不能让整机输入变卡"的兜底。

## 3. 安全模式 --safe

`
MouseWheelEnhancement.exe --safe
`

只打开界面：**不装钩子、不改系统行数、不加速**。用来回答"电脑变卡是不是这个程序"——
安全模式下它与没运行完全等价。

## 4. 全屏直通

前台窗口是独占全屏（游戏 / 全屏视频：无标题栏且铺满显示器）时，滚轮原样放行，
不加速也不摊帧。判定结果缓存 500ms，不在热路径上反复查询。

## 验证

--selftest **390 项**全过（含 13 条表驱动断言）；--featurecheck 通过。
--smoke 返回 5 —— 本机有另一个实例持有全局钩子（"注入 16/16 次、钩子接管 0 次"），
环境冲突，与本版改动无关。

## 还没做的（下一版，按此顺序）

| 项 | 原因 |
|---|---|
| 应用健康页（最近识别列表） | 需要新 UI 页 + 环形缓冲，单独一轮更稳 |
| 每应用完整手感（τ/惯性/帧数覆盖） | 要动配置 schema 与右键菜单，需迁移测试 |
| 中键拖拽平移 | 新增鼠标按键状态机，风险最高，必须单独压测 |
| 横向滚动摊帧 | 需要新的注入节拍，避免和纵向互相抢 |
| 边界回弹 | 拿不到目标滚动位置，需要先做"是否到底"的探测 |
| UI 像素基线回归 | 要提交基线图 + 比较器，属于测试基建 |

一次性把这些全塞进全局输入钩子，正是这几周出事的方式。所以这一版先交付"不会再变坏"的部分。
